# Phase 5：成员 Console 与管理闭环

日期：2026-09-27。当前为组内邀请制。本文记录本地实现与验证；生产域名、服务器及 SMTP 仍待配置，未部署线上，也未触发真实通知。

## 入口和功能

| 路径 | 功能与权限 |
| --- | --- |
| `/app` | 主题雷达、快速个人偏好；无订阅时提示建立第一份订阅 |
| `/app/subscription` | 本人订阅、首次引导、草稿预览、保存及版本冲突处理 |
| `/app/briefs` | 本人最近 100 个结果版本、最新简报、预览与显式站内成版 |
| `/app/briefs/:editionId` | 私人版本深链接，登录后仍按本人所有权校验 |
| `/app/library` | 获准阅读的合格内容及有效历史收藏，支持搜索和筛选 |
| `/app/saved` | 本人收藏；内容撤回或失去权限后不显示 |
| `/app/members` | 课题组管理员邀请、成员授权、停用和邀请状态 |
| `/app/topics` | 管理员维护全目录；主题负责人维护已授权的主题 |
| `/app/operations` | 管理员查看批次、站内组装汇总和审计 |
| `/admin` | 保留现有 GitHub 管理工作台，包含群体报告、运行中心和配置版本 |

成员入口不会加载 GitHub Provider，也不要求 PAT。生产由成员服务提供同源静态 Console 和 `/api/member`；服务根路径跳转到 `/app`。静态 Pages 的 `#/app` 兼容入口继续保留，但没有同源成员服务时会显示未开放，不能单独用于真实成员部署。

## 订阅和组装

订阅支持主方向、按顺序分配的次方向、子方向、重点关键词、排除词、内容类型、条数、主方向比例、代码筛选、开源偏好、频率、首次回顾范围和接收渠道意愿。重叠主题共用事件去重规则，内容不足时保留空缺。

- **预览当前草稿**：把尚未保存的完整设置交给服务端组装，不写订阅、反馈或个人历史。
- **保存个人订阅**：携带 `baseRevision`，仅保存订阅；不会生成正式简报或发送消息。
- **版本冲突**：保留本地草稿。读取最新版本后，对不同字段合并，对双方同时修改的字段逐一选择；确认合并后仍须明确保存。
- **暂停**：保存 `frequency=paused` 后，后续组装返回暂停状态。既有历史继续可读。当前尚无个人自动调度队列。
- **生成站内简报**：明确确认后创建固定版本及收录历史。网络结果不明时，当前页面重试沿用同一 `requestId`，不盲目创建新的请求。
- **空结果**：可以保存结果记录；暂停、未到订阅日或无合格内容不会变成已收录历史，也不会凑数。

页面显示主次归属、质量/相关性、入选原因、关键词、主题判断和原文引用。浏览器收到的是个人版本展示投影，完整可重放协议仍保留在服务端。

## 内容库、反馈与收藏

内容库使用新的认证 `GET library`，包含当前完整合格候选和本人历史中仍有效的收藏。按事件合并交叉主题，不使用雷达展示条数作为个人组装输入。搜索与筛选只处理本次获准返回的条目，不代表未采集内容或全互联网检索。

已读、收藏和不相关反馈通过服务端保存；撤回引用本人的反馈 ID。页面根据服务端状态显示可撤回操作，同一类存在多条活跃反馈时逐条撤回。只读成员只能阅读与预览。

历史收藏逐条执行当前主题权限和撤销检查。管理员不能通过成员 API 读取其他人的私人简报、订阅或收藏。复制私人深链接给其他成员仍会被拒绝。

## 管理页面

主题管理提供名称、启停、权重、优先级、关键词、别名、排除词、研究范围、正反例、子方向、相关性阈值和雷达上限。管理员可新增；负责人只能维护已有授权主题。删除有明确确认；版本冲突保留草稿并要求核对当前版本。

主题修改后，旧评估不会自动套用新目录。运营页分别展示“批次已经 ready”和“批次是否匹配当前目录”；需等待引擎按新目录重评估并导入。正式启用服务目录前，按 [Phase 4 引擎集成说明](https://github.com/No1dry/FeishuBrief/blob/main/docs/phase4-integration.md) 关闭旧 GitHub 路径的主题写入，设置 `EDITORIAL_PROFILE_PATH`。本次没有擅自切换生产工作流。

运营页仅展示实际导入元数据、个人站内成版计数和审计，不展示其他成员私人正文。当前没有持久化失败导入日志，因此界面不虚构失败记录或运行中任务。旧群体运行中心与报告仍由 `/admin` 管理。

## 会话、深链接与内容策略

`MemberSessionProvider` 统一管理会话、能力、请求取消和页面清理。账号或页面变化会卸载旧组件，迟到请求不能回填旧内容。进入后台、退出、跨标签会话变更和浏览器历史恢复均会清空并重新校验；隐藏标签不会因广播重新装载私人内容。

退出有独立进行中状态。服务端尚未确认退出时，不允许可见性变化或跨标签广播重新装载旧会话；退出失败后保留空页面并提供重试。验证码、邀请和私人内容均不保存到 localStorage 或 sessionStorage。

生产服务为 `/app` 提供仅同源连接的 CSP，为 `/admin` 单独允许 GitHub API。服务在 HTML 写入入口标记；跨成员/管理员入口必须完整加载新文档，使响应头策略随之切换。脚本仅同源，禁止嵌入、对象、框架，响应禁缓存并设置 no-referrer。样式保留 `unsafe-inline` 以兼容现有 React 行内样式，未开放内联脚本。

## 验证与复现

最终结果（2026-09-27）：Console **60 项浏览器测试全部通过**，生产构建通过；Member **29 项测试全部通过**，类型检查及四份引擎文件一致性校验通过。最终构建另通过真实本机 Chrome/HTTP 联调，包括旧管理员 hash 链接跳到成员文档后的 CSP 隔离。已查看桌面简报、375px 收藏、375px 主题管理及 320px 成员管理截图。

Console：

```powershell
npm test
npm run build
```

Member：

```powershell
npm run typecheck
npm run engine:check
npm test
```

真实本机联调使用生产构建、真实 HTTP API、内存 SQLite、模拟邮件及两个独立浏览器账号。从 Member 目录运行：

```powershell
node --import tsx ../FeishuBrief-Console/scripts/check-member-live.ts
```

需要两个同级工程的依赖已经安装、Console 已构建及本机 Chrome；默认只监听 `127.0.0.1:5291`，可通过 `CONSOLE_LIVE_PORT` 选择空闲本机端口。测试结束会关闭浏览器、服务和内存数据库。截图为合成内容，保存在 Console 的私有忽略目录 `test-results/member-live`。

验证覆盖邀请登录、草稿零写入、订阅、固定站内版本、收藏持久化、手机布局、管理员运营、跨成员拒绝、退出及 CSP。所有测试仅使用合成数据和本机接口，没有采集、真实模型、SMTP、飞书或 PushPlus 外发。
