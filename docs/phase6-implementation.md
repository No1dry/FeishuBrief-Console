# Phase 6 Console：个人通知

日期：2026-09-27。本地实现使用同源 Member Service；实际 HTTPS、SMTP、飞书及 PushPlus 账号仍需部署验收。

## 成员入口

访问 `/app/notifications`（导航“接收与通知”）：

1. 查看服务器已配置的个人渠道。未配置时展示原因，不能把渠道选择当作已绑定。
2. 飞书：开始绑定 → 把一次性绑定码发给应用机器人私聊 → 刷新状态 → 确认绑定。成员不输入 chat_id / open_id。
3. 微信：扫描专属好友二维码 → 等待服务端核实好友并发送绑定验证码 → 在原页面输入 8 位码。二维码为同源受认证图片，好友及发送 Token 不进入浏览器。
4. 选定自己的固定站内版本，单独确认发送。网络结果不确定时使用原 `requestId` 重试查询该次任务，不另建发送意图。
5. 调整个人计划的 `HH:mm` 时间，首版固定 `Asia/Shanghai`；默认关闭。服务端运行开关关闭时会显示未运行。保存冲突保留草稿供成员重新确认。
6. 解绑需确认，会取消该渠道尚未发送的任务。个人订阅暂停或账号停用也会由服务器立即取消未发送工作。

飞书/微信收到“版本已更新”的提醒及本人登录后可读的固定版本链接。正文留在成员 Console；旧的群体完整简报保持原推送方式。保存订阅、预览和生成站内版本不会顺带发送外部消息。

## 管理员入口

`/app/deliveries` 展示投递固定版本、成员、渠道、状态与重试次数。管理员可以：

- 查询具有实际查询能力的平台消息 ID。
- 对无法自动查询的未知结果记录人工核对说明；记录后状态仍是“结果待核对”。
- 对已结束或已人工核对的记录补发，填写原因并明确确认重复风险。固定原成员、版本和绑定，不能随意改投其他账号。

同一版本还有发送中、待发送、安全重试或未核对的未知记录时，不允许通过选择旧记录绕过核对。平台受理或平台确认都不代表成员已读。只读成员无法绑定、改计划或发消息；普通成员无法进入管理员投递管理。

运营页使用真实队列计数、消费者运行情况、计划开关与配置人数；审计页显示绑定、计划、发送、核对和补发事件。群体运营仍由 `/admin` 原界面负责。

## 私人数据与验证

新页面继承统一会话 Provider 的注销、隐藏页、跨标签和账号切换清空。异步结果必须匹配当前会话；不把绑定码、验证码、私人简报或队列存入 localStorage/sessionStorage。能力缺失时不会使用模拟记录替代真实服务。

浏览器测试全部拦截平台 API；真实本地联调使用构建后的 Console、原生 HTTP 成员服务、临时 SQLite、注入邮件与模拟发送器。联调覆盖站内版→签名加密回调绑定→单次发送→定时设置→管理员补发→解绑取消，以及既有登录、收藏、移动端、跨用户拒绝和退出。没有真实邮件、消息或模型调用。

验证记录：全套 69 项浏览器测试通过；后续新增两项回归后，最终 11 项通知专项全部通过，当前共 71 项。最终 `npm run build` 通过。真实 HTTP 联调使用最终构建执行成功，3 封内存邮件、1 次模拟投递，无外网请求；桌面与 375px 通知截图已检查，320px 布局由浏览器专项覆盖。

详细接口见 [Member API](https://github.com/No1dry/FeishuBrief-Member/blob/main/docs/api.md)，环境及平台配置见 [Phase 6 接入](https://github.com/No1dry/FeishuBrief-Member/blob/main/docs/phase6-implementation.md)。
